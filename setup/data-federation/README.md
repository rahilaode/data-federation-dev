# Data federation (Teiid)

Teiid 16.0.0 on WildFly 19.1.0 federates the two sources into the VDB `npd`
(`deployments/npd-vdb.xml`, generated by `setup/npd/tools/gen_vdb.py`), which holds the
federated schema Σ_S:

| Model | Kind | Content |
|---|---|---|
| `reporting` | physical (PostgreSQL, JNDI `java:/pgsql-reporting`) | 25 foreign tables: wellbores, seismic, stratigraphy, production |
| `registry` | physical (MySQL, JNDI `java:/mysql-registry`) | 45 foreign tables: licences, fields, discoveries, companies, facilities |
| `services` | virtual | views `v_wellbore_mud`, `v_field_investment`, `v_wellbore_core_ft` (scenarios A007–A009) |

The foreign tables are declared with explicit DDL (`CREATE FOREIGN TABLE`) with primary keys
only; the 11 foreign keys that cross the two sources do not exist in either database. Every
`reporting` table and column carries a quoted `NAMEINSOURCE` (`'"wlbPoint"'`), because
PostgreSQL folds unquoted names to lower case (ADR-0029). Text longer than Teiid's 4,000-character
string limit (`apaAreaGeometry_KML_WGS84`) is a `clob`.

| Host port | Use |
|---|---|
| 31000 | Teiid JDBC (Ontop connects here) |
| 35432 | Teiid ODBC, PostgreSQL protocol (Knowledge reads `SYS.*` and `SYSADMIN.*` here) |
| 19990 | WildFly management API (the Executor deploys VDB versions here) |
| 18080 | WildFly HTTP |

The image (`Dockerfile`) downloads Teiid from Maven Central and checks its SHA-1, creates the
users (`admin` in ManagementRealm, `user1` in ApplicationRealm), and runs
`virtual-db-config/setup.cli`, which installs the JDBC drivers and datasources and puts the
deployment scanner in manual mode for XML files. The VDB is not baked into the image: it is
deployed from the mounted `deployments/` folder when a `npd-vdb.xml.dodeploy` marker is
present (`start.sh` creates it). `setup.cli` is baked into the image, so a change to it needs
`docker-compose build` (`start.sh` builds).

The container runs with `-Xmx1g -Xss16m` (`JAVA_OPTS` in `docker-compose.yaml`). Teiid resolves a
UNION chain recursively, and with the default 1 MB thread stack a query such as
`SELECT * WHERE { ?s a ?c }` over the NPD mapping (about 1,500 UNION branches) fails with
TEIID30019 `StackOverflowError` (ADR-0030).

VDB versions created by ASCAM are deployed through the management API, not written to
`deployments/`, so `npd-vdb.xml` stays the base state. WildFly keeps them in the volume
`teiid-standalone-data`; `./start.sh` removes it, `./restart-ascam.sh` keeps it.
